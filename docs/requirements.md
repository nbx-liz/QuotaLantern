# QuotaLantern 要件

版：0.1（2026-10-22）／追跡：#1

## 1. 目的

AI ツールで作業を続けながら、次の値を小さな常駐 UI で確認できるようにする。

- 利用枠の残り
- 利用枠がリセットされるまでの時間
- 取得できる場合のコンテキスト使用率
- 安全に取得できる場合の、観測範囲内のトークン消費

表示の速さだけでなく、**その数値が何を対象にし、いつの値なのか**が誤解なく伝わることを重視する。
安全に取得できない値は推測や非公式な手段で補わず、「未取得」「非対応」と表示する。

## 2. 決定状態

| 区分 | 内容 |
| --- | --- |
| 確定 | 製品名 QuotaLantern。macOS / Windows 両対応。気軽なリアルタイム可視化。利用者の情報を残さず、セキュリティを優先する。MIT OR Apache-2.0 の OSS として公開（ADR-0007） |
| 初期設計案 | Claude Code と Codex を先行対応。常駐パネル。共通 Rust コア（ADR-0001）。Tauri 2 は条件付き候補（ADR-0003）。独自サーバーを持たない |
| 要検証 | 利用形態ごとに取得できる項目、公式クライアントを動かすことの副作用（ADR-0004）、WebView の非保存、WSL2 連携 |
| 未決定 | 最低 OS 版、Intel Mac / Windows ARM64 の扱い（ADR-0006）、署名費用、配布主体、名称の商標確認（ADR-0008） |

### 表記

- **MUST**：必須の実装条件
- **SHOULD**：推奨
- **GATE**：実測とレビューに合格するまで公開を止める条件

性能値・閾値・上限値は、この製品が置く暫定値である。提供元が保証する値ではない。

## 3. 機能要件

優先度：**P0** は MVP に必須、**P1** は取得経路と安全性の条件が成立した後、**P2** は後続検討。
安全性が不足していることを理由に、P0 の条件を暗黙に緩めてはならない。

| ID | 優先度 | 要件 | 合格条件の要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | macOS のメニューバー、Windows の通知領域に常駐する | 両 OS で起動・表示・終了ができる |
| FR-02 | P0 | サービスごとに利用枠とリセット時刻を表示する | 存在する枠だけを表示する。欠損を 0 として表示しない |
| FR-03 | P0 | 取得状態・対象範囲・鮮度を表示する | 未取得、停止、非対応、エラーを区別して表示する |
| FR-04 | P0 | 接続の開始・停止と、メモリ内データの消去 | 停止後は値を更新しない。消去後は値を復元しない |
| FR-05 | P0 | 任意で使える小型の固定パネル | 両 OS で表示でき、作業中のフォーカスを奪わない |
| FR-06 | P0 | 取得できるコンテキスト使用率を別枠で表示する | 契約上の利用枠や累積トークンに換算しない |
| FR-07 | P1 | 観測範囲内の累積トークンと内訳 | 値の意味・区間・重複排除を検証できた経路に限る |
| FR-08 | P1 | 直近 60 分の推移 | メモリ内だけで保持する。欠損を補間して実測に見せない |
| FR-09 | P1 | アプリ内での残枠警告 | 鮮度が不明な値では確定的な警告を出さない |
| FR-10 | P1 | WSL2 内の取得部と Windows 側 UI の連携 | 中間ファイルを使わない。WSL を勝手に起動しない |
| FR-11 | P2 | ChatGPT の通常チャットの利用量 | 網羅性・遅延・非保存を確認できてから提供する |

## 4. MVP の扱い

- 公開目標は、両 OS で Claude Code と Codex の残枠を表示すること。
- どちらかの取得経路が安全性ゲートに不合格なら、その経路を「対応済み」と表示しない。
  機能を縮小して公開するかはプロダクト責任者が判断し、対応表に制限を明記する。
- トークン数を安全に取得できない段階では「残枠モニター」と説明する。
  「すべての AI のトークンをリアルタイム計測」とは宣伝しない。
- API キーの従量利用と、月額契約の利用枠を同じものとして扱わない。

## 5. 量の区別

次の四つは別の指標として扱い、互いに換算しない。

| 量 | 性質 | 扱い |
| --- | --- | --- |
| 利用枠（quota） | 提供元が報告する使用率のスナップショット | 加算しない。枠同士を合計しない |
| コンテキスト（context） | セッションごとの使用率のスナップショット | 減少しても「トークンが戻った」と解釈しない |
| トークン消費（token_counter） | 観測開始以降の累積差分 | 検証済みの経路だけで集計する |
| 料金 | — | 初期版では推計しない |

- 残枠の比率から「残りトークン数」を逆算しない。
- リセット予定時刻を過ぎても、残り 100% に自動で切り替えない。新しい値を待つ。
- 同じアカウントの枠が複数の端末やセッションで見えても合計しない。
  初期版はサービスごとに取得元を 1 つ選ぶ。アカウント ID を保存して自動で統合する設計は採らない。

## 6. UI と導入の原則

- 新規アカウント登録、管理者権限、画面収録・アクセシビリティの権限、ブラウザ情報へのアクセスを、
  日常利用の前提にしない。
- 導入に必要な設定変更は、変更内容を提示した上で、利用者の明示操作で行う。
  既存の設定を無断で上書きしない。
- 初回は空のパネルから始め、連携先・受信する情報・発生する通信を説明する。
  利用者が連携を 1 つずつ有効にする。
- 「パネルを閉じる」は常駐を続ける。「計測停止」は取得を止める。
  「データ消去」は計測を止めてメモリ内の状態を破棄し、再開には明示操作を要する。
  「終了」は QuotaLantern が起動した子プロセスも終了させるが、利用者が元から動かしていた AI プロセスは終了させない。
- キーボード操作、読み上げラベル、拡大表示に対応する。警告を色だけで伝えない。
- 画面ロック中は使用量を表示しない。
- 初期版には OS 通知、クリップボードへの転送、共有・エクスポート機能を設けない。
- 初期の UI 言語は日本語。翻訳キーは分離しておく。

## 7. 表示状態

状態は取得元全体と指標ごとに持つ。トークンが非対応でも、取得できている残枠は表示する。

| 状態 | 表示 | 値の扱い |
| --- | --- | --- |
| disabled | 未接続／計測停止 | 最新値として表示しない |
| connecting | 接続中 | 以前の値や架空の値を出さない |
| waiting | 接続済み・初回データ待ち | 数値は「—」 |
| available | 取得済み | 最終受信時刻と対象範囲を併記する |
| stale | 古い値 | 最終値を薄く表示し、鮮度が不明であることを明示する |
| unsupported | この環境では未対応 | 0、無制限、残り 100% として表示しない |
| auth_required | 公式ツールでの再認証が必要 | 入力フォームを出さない |
| error | 計測エラー | 固定のエラーコードだけを表示する。生のレスポンスを出さない |

「受信が新しい」ことと「提供元の値が新しい」ことは区別する。
提供元の時刻がない場合は「最終受信」と表示し、再送や再描画だけで鮮度を更新しない。
stale と判定する条件は未決（ADR 台帳の未決論点 Q-01）。

## 8. 非目標（初期版に含めないもの）

長期の履歴分析、クラウド同期、組織の課金管理、会話の閲覧・削除、AI への指示実行、
ブラウザ拡張、Cookie の抽出、非公開 API の解析、通信の傍受、利用枠のリセット操作、
AI モデルを動かして計測値を推測する機能、利用データの永続キャッシュ、追跡・解析 SDK。

取得できないものは、抜け道の実装ではなく「未対応」の表示と仕様上の制限として扱う。

## 9. 初期の対象環境

| 環境 | 方針 |
| --- | --- |
| Apple silicon Mac | 初期の必須実機。最低 macOS 版は UI 試作後に決める |
| Windows 11 x64 | 初期の必須実機。ネイティブ実行経路を確認する |
| Windows 11 x64 + WSL2 | P1。1 つのディストリビューションから始める |
| Intel Mac / Windows ARM64 | ビルドできるかと実機検証は別に判断する（ADR-0006） |
| Linux 単体 / SSH / コンテナ | 初期版の対象外。取得部の設計には拡張の余地を残す |

実機での確認結果がない OS・CPU・版を「対応」と記載しない。

## 10. 外部仕様の参照

外部仕様の事実は、各 ADR に出典と確認日を付けて記録する。
公開文書があることと、利用者の環境で実際に取得できることは別であり、
対応する CLI の最低版は試作で確認した上で対応表に記載する。
