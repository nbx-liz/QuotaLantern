# ADR-0001：共通 Rust コアと OS 別 UI

- ステータス：Proposed
- 決定者：技術責任者
- 期限：G0 終了
- 追跡：#1

## 背景

macOS と Windows で同等の基本機能を提供する必要がある。
取得・集計・状態管理を OS ごとに作ると、非保存や二重計上防止の規則が OS 間でずれる。

## 決定（案）

取得・正規化・集計・状態管理を、UI から独立した Rust のコアにまとめる。データの流れは次のとおり。

```text
公式ツールの計測出力
  -> 取得部（型を検証し、許可した項目だけを抽出）
  -> ローカル IPC（正規化したイベントだけを渡す）
  -> 共通コア（集計・状態・重複排除。メモリ内のみ）
  -> OS 別の常駐 UI（数値と固定ラベルだけを表示）
```

| コンポーネント | 責務 | 禁止事項 |
| --- | --- | --- |
| Claude 取得部 | Status line の入力から必要な項目だけを抽出する | transcript_path を開く、入力全体を複製する |
| Codex 取得部 | 固定の読み取り RPC を呼び、結果を正規化する | 認証ファイルを読む、任意の RPC を呼ぶ、本文を購読する |
| 共通コア | 状態機械、期間、集計、保持期限 | 外部通信、利用データの永続化 |
| UI | 常駐、パネル、アクセシビリティ | 外部 HTML、任意の shell、任意のファイル読み取り |
| 導入支援 | 変更手順と解除手順を提示する | 無断の設定変更、秘密を含む設定の丸ごと保存 |

リポジトリの構成：

```text
crates/core/            状態・集計・時刻（OS 非依存）
crates/protocol/        内部イベントの型と検証
crates/adapter-claude/  Claude Code Status line の許可項目抽出
crates/adapter-codex/   Codex App Server の読み取り RPC
crates/ipc/             OS 別のローカル IPC
apps/desktop/           採用した UI（ADR-0003）
schemas/                内部イベント契約の正本
tests/fixtures/         合成データのみ
```

実装上の規則：

- 依存は lockfile で固定する。コアは OS に依存させない。
- 提供元の生の入力型と内部の型を分ける。
- 秘密を含み得る型に汎用の `Debug` 表示を付けない。
- 外部のエラーを文字列のまま上位へ伝えず、固定のエラーコードに変換する。
- プロセスは一般ユーザー権限で動かす。コマンドの引数は配列で渡し、shell 文字列に連結しない。

## 検討した代替案

- OS ごとのネイティブ実装（Swift / C#）：UI の品質は高いが、規則の実装が二重になる。UI 層だけをネイティブにする余地は ADR-0003 で残す。

## 影響

Rust を採用したこと自体を安全性の根拠にしない。境界、依存、`unsafe` の使用をレビューする。
プロセスを分けても OS の権限が制限されるわけではないので、実際の権限・ファイル・通信アクセスは別に検証する。

## 受入条件

- コアと protocol が OS 固有のコードなしで macOS / Windows / Linux の CI でビルド・テストできる。
- UI を差し替えても、コアとイベント契約を変更せずに済む。
