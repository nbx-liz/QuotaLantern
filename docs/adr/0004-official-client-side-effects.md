# ADR-0004：公式クライアントを動かすことの副作用

- ステータス：Proposed
- 決定者：技術責任者＋セキュリティ担当
- 期限：G0 終了
- 追跡：#1

## 背景

Codex の利用枠は、認証済みの公式 CLI が提供する App Server（stdio）経由で取得する案である。
App Server は `initialize` → `initialized` で接続し、利用枠を `account/rateLimits/read` で返す。
アクティブなスレッドのトークン通知（`thread/tokenUsage/updated`）は別の API であり、
別プロセスの全セッションを監視できる根拠にはならない。

出典：<https://learn.chatgpt.com/docs/app-server>（2026-10-21 確認。実装開始時に再確認する。）

App Server は読み取り専用のサービスではない。また、公式プロセスを起動・照会すると、
追加のログ、状態 DB、認証の更新、外部通信が発生する可能性がある。提供元のプロセスだからといって、無条件に保証の対象外とはしない。

## 決定（案）

- QuotaLantern は認証ファイル、Cookie、API キー、OS の資格情報ストアを読まない。独自のログインも提供しない。
- 実装上の許可リストは、接続の初期化と `account/rateLimits/read` だけにする。
- UI から method や params を自由に指定できる入口を設けない。
- thread / turn の開始・変更、任意コマンドの実行、ログイン、クレジットの消費、メール送信を行わない。
- 未知のサーバー要求は実行せず、固定のエラーを返すか切断する。標準エラーを親のコンソールにそのまま継承しない。
- primary / secondary を「5 時間」「週次」と固定で呼ばない。応答に含まれる期間とバケットを使う。
- `rateLimitsByLimitId` と互換用の `rateLimits` を二重に計上しない。
- トークン通知は、本文を受信せずに必要な計測だけを取れると確認できるまで無効にする。
  通知の除外リストは未知のイベントへの防御にならない。
- 認証が切れたら、公式ツールでの再認証を案内する。秘密情報を入力させない。
- 実行ファイルは、利用者が選んだ公式のインストールを検証して使う。カレントディレクトリにある同名の実行ファイルを誤って起動しない。
- 異常終了した子プロセスの自動再起動には、回数の上限と待ち時間を設ける。

## 検討した代替案

- 認証ファイルや非公開 API を直接使う：禁止事項に当たるため採らない。
- ChatGPT の `account/usage/read`：通常チャット全体の網羅性と鮮度が未確認。MVP では呼ばず、未対応と表示する。

## 影響

禁止データの追加保存を抑えられない場合、その取得経路は公開しない。

## 受入条件

- 公式プロセスの起動・照会の前後で、ファイル・設定・通信の差分が説明でき、禁止データの追加保存がない。
- 許可リストにない RPC を、どの入口からも送れない。
