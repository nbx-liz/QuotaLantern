# 保証境界：非保存の定義とデータ分類

版：0.1（2026-10-22）／追跡：#1

この文書は、QuotaLantern が利用者に対して何を保証し、何を保証しないかを定める。
`docs/requirements.md` より優先する（[CONTRIBUTING.md](../../CONTRIBUTING.md) の優先順位を参照）。

## 1. 保証すること

**QuotaLantern 本体と同梱コンポーネントは、利用データを永続化しない。**

ここでいう「永続化」には次をすべて含み、例外として扱わない。

- 終了時に削除する予定の一時ファイル
- 暗号化したデータベース・キャッシュ
- 識別子の安定したハッシュ値（ソルト付きを含む）
- ログファイル、診断の添付、クラッシュレポート
- UI ランタイム（WebView 等）のストレージ、キャッシュ、セッション復元状態
- OS の設定領域・レジストリへの利用データの書き込み

アプリのバイナリや静的な配布物は、利用データとは区別する。

あわせて次を保証する。

- QuotaLantern のコアと UI は外部と通信しない。公式プロセス経由の通信は、機能ごとに説明して利用者が明示的に有効化する。
- 独自の解析・広告・クラッシュ収集・更新確認のサービスを持たない。
- 会話の本文や認証情報を取得する経路を持たない。

## 2. データ分類

| データ | 受信・メモリ上での扱い | 永続化 |
| --- | --- | --- |
| プロンプト、回答、コード、添付の内容 | 取得する経路を設けない | 禁止 |
| API キー、OAuth トークン、Cookie | QuotaLantern は取得しない | 禁止 |
| メールアドレス、組織 ID、パス、会話タイトル | 意図して取得しない。避けられない受信は取得部で破棄する（ADR-0002） | 禁止 |
| セッション識別子 | 必要な対応付けのためだけに、取得部のメモリ内に置く。生の ID を取得部の外へ渡さない | 禁止 |
| 使用量、残枠、更新時刻、短期の推移 | 表示と集計に必要な期間だけ保持する | 禁止 |
| ログ・エラー | 固定のエラーコードと件数だけをメモリ内に置く。生の入力は含めない | 初期版は禁止 |
| 接続設定・表示設定 | 初期版はメモリ内 | 許可する項目を承認するまで自動保存しない（ADR-0005） |

### 利用者への説明（ADR-0002）

Claude Code の Status line から使用量を受け取るとき、Claude Code は同じ入力に、セッション ID、作業フォルダーのパス、
会話記録ファイルのパスなども含めて渡す。QuotaLantern の取得部はこれらを短時間メモリ上で受け取るが、
利用枠とコンテキストの数値だけを取り出し、残りは読み飛ばして破棄する。保存も転送もしない。

### 取得部の境界

- 提供元からの入力は、取得部で型を検証し、許可した項目だけを取り出す。
  入力全体を複製・保存・転送しない。
- 未知のフィールドは構文として読み飛ばし、その値を診断に出さない。
- 内部へ渡すのは正規化したイベントだけとする（`schemas/` が正本）。
  自由記述の文字列は原則として持たせない。
- 提供元の生のエラー文字列を上位へ伝えず、固定のエラーコードに変換する。

## 3. 保持の上限（暫定値）

| 対象 | 上限 |
| --- | --- |
| 推移 | 最大 60 分、1 分粒度 |
| 未接続になった系列 | 最大 60 分で破棄 |
| 系列数 | 全体で 128。超過したことを明示する |
| 内部キュー | 256 件 |
| 正規化イベント | 16 KiB |
| 提供元からの入力 | 1 MiB |
| JSON の入れ子の深さ | 16 |

利便性のために初期値や設定を記憶させる変更も、保存の追加としてレビューの対象にする。

## 4. 保証しないこと（隠さないこと）

メモリ内だけで処理しても、物理的な痕跡が一切残らないことは証明できない。次は製品の保証の外にある。

- OS のスワップ、ハイバネーション、OS 設定によるクラッシュダンプ
- 画面の撮影や画面共有
- OS や提供元サービス、公式クライアント自身が行う保存
- 管理者権限によるメモリの取得、同一ユーザーで動くマルウェア、侵害済みの端末

ただし、OS の機能を理由にアプリ側のキャッシュやログを許容しない。
既存の AI ツールの設定や OS の保護機能を、無断で変更・無効化しない。

公式クライアントの避けられない副作用が要件と衝突する場合は、保証を黙って狭めず、その取得経路を止める（ADR-0004）。
試験で見つかった保証境界外の痕跡は別欄に記録し、アプリ側の不合格と混ぜて隠さない。

## 5. 公開を止める条件（GATE）

次のいずれかが確認された場合、公開を止める。

- 利用データの保存
- 会話や認証情報の取得
- 外部への説明されていない送信
- 残枠の誤った集計、同一データの二重計上
- 任意の RPC の実行

検証中の機能はリリースビルドに含めないか、利用者が誤って有効化できない状態にする。

## 6. 判断の原則

- 仕様が不明なときは fail-closed とし、該当する計測を止める。ただし AI の作業自体は止めない。
- 禁止事項を増やすのではなく、許可するデータ・RPC・保存物を列挙する（許可リスト方式）。
- 対応範囲を狭める判断を許す。取得できないものを抜け道で補わない。
